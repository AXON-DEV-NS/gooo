# ADR-0001: البنية التقنية وتجربة التلفاز لتطبيق «جووو»

- **الحالة:** معتمد للتنفيذ (الإصدار ١.٠)
- **التاريخ:** 2026-11-16
- **المستند المرجعي:** الوثيقة المرجعية الشاملة لتصميم وبناء «جووو» (الإصدار ٢.٠)

---

## السياق (Context)
يستهدف «جووو» العمل لوحة تشغيل يومية ثابتة على شاشة تلفاز توشيبا عبر متصفحه المدمج، مع عدم معرفة الطراز الدقيق أو إصدار المتصفح مسبقاً. تتطلب الواجهة قراءة واضحة من مسافة الأريكة، تحكماً كاملاً بالريموت (أسهم الاتجاهات + التأكيد + الرجوع)، وضعاً فاتحاً مريحاً، عملاً مقبولاً عند انقطاع الإنترنت، وعدم تداخل الأصوات أو فقدان البيانات.

## الخيارات المدروسة (Options Considered)
1. **إطار واجهة ثقيل (React/Next/SSR + مكتبات أنيميشن كبيرة):** يرفع حجم الحزمة ويستهلك ذاكرة متصفح التلفاز وقد يتعطل على متصفحات التلفاز القديمة.
2. **ملفات HTML/CSS/JS ثابتة دون أدوات بناء أو اختبارات:** سهلة التشغيل لكنها تفتقر إلى اختبارات وحدات آلية وإعادة تحميل منظم وتحزيم متوافق.
3. **Vite + Vanilla JavaScript المعيارية + Vitest (+ دعم التوافق مع متصفحات التلفاز):** حزمة خفيفة وسريعة بدون عبء إطار واجهة ثقيل، فصل واضح بين العرض والخدمات والتخزين، واختبارات آلية للوقت والتنبيهات والترحيل.

## القرار (Decision)
اعتماد **Vite + Vanilla ES Modules + CSS Tokens + Vitest** مع المبادئ التالية:
- **استقلالية تامة بدون مكتبات ثقيلة في الواجهة:** استخدام متغيرات CSS مركزية (Warm Ivory light default + Emerald/Gold accents + optional night mode)، وخطوط محلية/احتياطية واضحة (`Amiri` للعناوين، `IBM Plex Sans Arabic` / `Noto Naskh Arabic` مع بديل النظام).
- **توافق الدقتين 720p و 1080p:** تخطيط شبكي مرن بنسبة `16:9` مع هامش أمان داخلي `4%` من حواف الشاشة لتفادي قص الـ Overscan.
- **شاشة فحص تلفاز مدمجة (Phase 0 Diagnostics):** صفحة اختبار فورية تقيس دقة العرض الفعلية، دعم `localStorage`، سياسة الصوت، أزرار الريموت الحقيقية (`Arrow*`, `Enter`, `Backspace/Escape`, مفاتيح التلفاز الشائعة `461` / `10009` / `XF86Back`)، وحالة الشبكة.
- **حساب وقت فعلي لا يعتمد على عدّ الثواني المتراكم:** حساب الفارق الزمني الحقيقي (`targetMs - Date.now()`) مع توقيت `Africa/Cairo`.
- **صوت آمن وتخزين متين:** بوابة تفعيل صريحة («تفعيل الصوت»)، صوت محلي مركّب (WAV/Web Audio) لا يحتاج إنترنت، عدم التداخل، تنبيه مرئي عند الفشل، ومخطط بيانات مرقم (`schemaVersion`) مع ترحيل آمن وتصدير/استيراد JSON مُتحقق منه.

## التبعات والمقايضات (Consequences)
- **الإيجابيات:** إقلاع فوري على متصفحات التلفاز محدودة الذاكرة، استقرار بصري، تغطية اختبارية للمنطق الحساس، وسهولة النشر على استضافة ثابتة (GitHub Pages / Vercel).
- **السلبيات / الالتزامات:** كتابة محرك التنقل المكاني بالريموت وتحديث DOM الموضعي يدوياً ضمن وحدات معزولة بدلاً من الاعتماد على إطار مكونات ضخم. يتطلب النشر النهائي على تلفاز قديم تفعيل هدف متوافق (ES2018 / `@vitejs/plugin-legacy` عند الحاجة بعد فحص الطراز).
